* Overview

This file declares two tangled outputs:

- =init.el= — the =doom!= macro block that enables and configures Doom modules.
  Every module flag (=+flag=) and feature toggle lives here.
- =packages.el= — third-party packages not covered by Doom's built-in modules.
  Each =(package! ...)= entry is installed and pinned by =straight.el=.

After editing either section, tangle this file, then:
- For =init.el= changes: run =doom sync= in a terminal and restart Emacs.
- For =packages.el= changes: run =doom sync=; new packages will be fetched.

Reference: [[https://docs.doomemacs.org/latest/][Doom Emacs Documentation]]

* Generated File Headers                                           :noexport:

The lexical-binding cookie is mandatory on both files — it enables
compile-time variable scoping and is required by Doom's byte-compilation.

* Module Declarations

The =doom!= macro is evaluated once at startup to determine which Doom modules
to load. Each module is a directory under =~/.config/emacs/modules/=.
Flags (prefixed with =+=) enable optional sub-features within a module.

The modules are grouped by Doom's own category system: =:completion=,
=:ui=, =:editor=, =:emacs=, =:term=, =:checkers=, =:tools=, =:os=, =:lang=,
and =:config=.

#+begin_src emacs-lisp
(doom!

 ;; ── Completion ────────────────────────────────────────────────────────────────
 ;; In-buffer completion and interactive narrowing/selection.
 :completion
 (corfu +orderless)  ; Corfu for in-buffer completions; orderless for fuzzy
                     ; space-separated matching across any completing-read UI
 (vertico +childframe +icons)  ; Vertico + posframe child-frame UI + file icons

 ;; ── User Interface ────────────────────────────────────────────────────────────
 ;; Visual chrome, themes, and structural UI modules.
 :ui
 (doom +icons)       ; Doom's icon support via nerd-icons (replaces all-the-icons)
 dashboard           ; Startup splash dashboard with recent files / agenda
 hl-todo             ; Highlight TODO/FIXME/HACK/NOTE keywords in source
 (modeline +light)   ; Doom modeline; +light skips heavy git state computation
 ophints             ; Flash operator targets (yank, delete, etc.) in Evil
 (popup +defaults)   ; Intelligent popup window management with sane defaults
 (vc-gutter +pretty) ; Git gutter signs in the fringe; +pretty uses nerd-icons
 vi-tilde-fringe     ; Show ~ in fringe for lines beyond end of buffer (Vim feel)
 workspaces          ; Named workspace tabs via perspective.el
 (treemacs +icons)   ; Sidebar file-tree; +icons enables nerd-icons decorations

 ;; ── Editor ────────────────────────────────────────────────────────────────────
 ;; Text editing enhancements layered on top of Evil.
 :editor
 (evil +everywhere)  ; Vim modal editing in every buffer (not just prog-mode)
 file-templates      ; Snippet-based default content for new files (yasnippet)
 fold                ; Code folding via hideshow / ts-fold
 format              ; Auto-format on save via apheleia (uses per-lang formatters)
 multiple-cursors    ; Multi-cursor editing via evil-multiedit / evil-mc
 snippets            ; Yasnippet with Doom's built-in snippet library
 (whitespace +guess  ; Highlight trailing/mixed whitespace;
             +trim)  ; +guess infers indent style; +trim strips on save
 word-wrap           ; Soft word-wrap with =M-x +word-wrap-mode=

 ;; ── Core Emacs ────────────────────────────────────────────────────────────────
 ;; Doom wrappers around built-in Emacs subsystems.
 :emacs
 dired               ; Enhanced dired with Evil bindings and icons
 electric            ; Auto-close pairs (parens, brackets, quotes)
 tramp               ; Remote file editing via SSH / sudo (tramp.el)
 undo                ; Persistent undo history via undo-fu + undo-fu-session
 vc                  ; Version-control integration (magit supplements this)

 ;; ── Terminal ──────────────────────────────────────────────────────────────────
 :term
 vterm               ; Fast terminal emulator using libvterm (C library)
                      ; Requires libvterm shared library (winget install GnuWin32.Make then M-x vterm-compile)

 ;; ── Checkers ──────────────────────────────────────────────────────────────────
 :checkers
 (syntax -flymake)    ; On-the-fly syntax checking via flycheck (instead of flymake)
                      ; -flymake flag means: use flycheck, not the built-in flymake

 ;; ── Tools ─────────────────────────────────────────────────────────────────────
 ;; Integrations with external tools and services.
 :tools
 (eval +overlay)     ; Inline code evaluation; +overlay shows results in-buffer
 lookup              ; Go-to-definition, documentation, online search (xref)
 lsp                 ; Language Server Protocol client via lsp-mode
 magit               ; Full-featured Git interface
 tree-sitter         ; Structural syntax trees for smarter highlighting/editing
                     ; Requires Emacs 29.1+ — grammars pulled for :lang js + web

 ;; ── OS Integration ────────────────────────────────────────────────────────────
 :os
 (:if (featurep :system 'macos) macos)  ; macOS-specific tweaks (no-op on Windows)

 ;; ── Languages ─────────────────────────────────────────────────────────────────
 ;; Per-language modules. Each installs a major mode, LSP config, and
 ;; optional tree-sitter grammar.  +lsp wires the language into lsp-mode.
 ;; +tree-sitter enables structural editing and better highlighting.
 :lang
 emacs-lisp          ; Emacs Lisp — elisp-mode, eros eval, helpful
 (javascript +lsp    ; JS/TS/TSX via typescript-ts-mode + LSP (ts-ls / eslint)
             +tree-sitter)
 (org +dragndrop)    ; Org Mode with drag-and-drop image attachment support
 markdown            ; Markdown preview via grip or pandoc
 json                ; json-mode + lsp-mode for JSON editing
 yaml                ; yaml-mode for YAML/TOML-adjacent files
 (python +lsp)       ; Python via python-mode + pyright/pylsp
 (rust +lsp)         ; Rust via rust-mode + rust-analyzer
 (web +lsp           ; HTML, CSS, JSX templates via web-mode + LSP
      +tree-sitter)  ; Pairs with javascript module for Vite/React stack
 sh                  ; Bash/sh/zsh via sh-mode

 ;; ── Configuration Layer ───────────────────────────────────────────────────────
 ;; Doom's own sensible defaults layer.  Always keep this last.
 :config
 (default +bindings  ; Doom's default keybindings (SPC leader, g/z prefixes)
          +smartparens))  ; Smartparens for structural pair management
#+end_src

** PKM — Denote

Denote provides a structured, filename-based personal knowledge management
system. Notes live under =~/Documents/org/notes/= as =YYYYMMDDTHHMMSS--title__tags.org= files.
The stable timestamp ID in each filename is the permanent link target for
=[[denote:ID]]= cross-references.

#+begin_src emacs-lisp :tangle packages.el
(package! denote)          ; Core: create, rename, link notes by ID
(package! denote-explore)  ; Visualise note graph and orphans
(package! denote-org)      ; Org-specific: org-capture templates, org-insert-link
#+end_src
