* Overview

Basic Memory is a local, offline memory backend shared across all AI coding
assistants: Claude Code, Cursor, Windsurf, VS Code Copilot Chat, and the
GitHub Copilot CLI.

Every memory is a plain Markdown file in =~/basic-memory/=. AI agents write
and read using MCP tools (=write_note=, =search_notes=, =build_context=,
etc.). The files live on disk like any other text � you can browse them in
Doom, search with =rg=, and version them with git.

** Org File Safety

*Your org files are never touched.* The bootstrap step works like this:

#+begin_example
~/Documents/org/notes/tools/example__tools_reference.org   ? ORIGINAL � read-only input
           �
           �  pandoc (reads, never writes back)
           ?
~/basic-memory/bootstrap/example.md ? NEW FILE � separate directory
#+end_example

Pandoc reads org files as source and writes brand-new Markdown files into
=~/basic-memory/bootstrap/=. Deleting =~/basic-memory/= has no effect on org notes; they remain in their original location.

** Why HTTP Transport (not stdio)

Each AI client that uses stdio would spawn its own =basic-memory= subprocess.
All subprocesses share the same SQLite index file and would produce
"database is locked" errors under concurrent writes. Running a single
persistent HTTP server on port 8765 eliminates contention entirely.

* Overview & Architecture

Basic Memory is a custom MCP (Model Context Protocol) server designed for offline, shared AI memory.

**Why Basic Memory?**
Agents like Claude Code, Cursor, and Windsurf often suffer from "context amnesia" between sessions. Basic Memory runs as a local HTTP server that exposes the Documents/org/notes/ directory to these agents as an indexed, queryable database. This acts as a permanent, shared brain across all AI tools on this machine.

=.gitattributes= enforces LF line endings on all text files (=* text=auto eol=lf=)
to prevent CRLF issues on Windows. If files are lost, recover from the local
SQLite database: =~/.basic-memory/memory.db= (chunked text survives in
=search_vector_chunks=; see changelog for the 2026-05-17 corruption incident).

** Project Path

Basic Memory uses =~/basic-memory/= as its default project directory.
All clients connect to the single shared =main= project.

* Startup � VBScript in Common Startup Folder

The server starts at login via a VBScript placed in the *all-users* Startup folder
(ProgramData � requires admin to install or replace):
=C:\ProgramData\Microsoft\Windows\Start Menu\Programs\StartUp\=

The VBScript calls a PowerShell helper script (=start-basic-memory-server.ps1=) rather than
launching Python directly. This two-layer design keeps the VBScript dead-simple
(no complex quoting) and keeps all process-launch logic in PowerShell where it
is easy to test and modify.

Chain: =startup-orchestrator.vbs= (Group 1) ? =start-basic-memory-server.ps1= ? venv =python.exe=

** Why not Task Scheduler

Task Scheduler was tried and abandoned. =basic-memory.exe= (and the copy in
=~/.local/bin/=) are both *uv trampolines* � thin launchers that resolve their
Python environment at runtime. They fail with =uv trampoline failed to
canonicalize script path= in non-interactive Task Scheduler sessions because
the path-resolution context is wrong. =uvx= was also tried; it worked but
downloaded the full environment on every fresh boot, making startup unreliable.

The fix is to invoke the venv Python directly, bypassing the trampoline.

** Windows Scripting Gotchas

Two issues encountered during setup:

*** VBScript � WScript.Shell.Run uses a stripped PATH

=oShell.Run "pwsh.exe ..."= fails silently: =WScript.Shell= does not inherit
the user's full =PATH= so =pwsh.exe= is not found. Always use the absolute path:

#+begin_example
"C:\Program Files\PowerShell\7\pwsh.exe"
#+end_example

*** PowerShell � Start-Process -ArgumentList does not quote arguments

=Start-Process -ArgumentList '-c', $code= joins elements with spaces but does
*not* add quotes around arguments that contain spaces. If =$code= contains
spaces (all Python =-c= payloads do), only the first word reaches Python.

Fix: add inner quotes manually using backtick-double-quote escaping:

#+begin_src powershell :tangle no
Start-Process -FilePath $python `
    -ArgumentList '-c', "`"$code`"", 'mcp', '--transport', 'streamable-http', ...
#+end_src

This produces the command line =-c "from basic_memory�" mcp �= where the
Python code is a single quoted argument.

** Real executable path

The uv tool venv lives at:

#+begin_example
%APPDATA%\uv\tools\basic-memory\Scripts\
#+end_example

Inline PowerShell invocation (idiomatic; use in scripts, not interactive shells):

#+begin_src powershell :tangle no

* Handoff: Architecture Migration (Windows Terminal -> WezTerm)

** The Migration
On May 28, 2026, the entire terminal architecture was migrated from Windows Terminal (UWP) to WezTerm (Win32). This was done to solve an inescapable race condition between Komorebi (which hooks window creation instantly) and Windows Terminal (which takes ~500ms to set its window title based on its profile).

** How the Quake Terminal Works Now
The user wants a Quake-style drop-down terminal (managed by WTQ) that floats and is ignored by Komorebi, while ALL other normal terminal instances are properly managed and automatically tiled on the "ops" workspace.

Because WezTerm is a native Win32 app, it allows us to set the Window Class at launch via command line arguments. WTQ is configured to launch WezTerm with the --class QuakeTerm argument.
When the window is spawned, its class is instantly QuakeTerm. Komorebi's ignore_rules natively match this class on millisecond zero, preventing it from ever being tiled or flashing.
Normal WezTerm instances do not have this class, so they are properly tiled.

** Important Constraints
- *Do not* use Windows Terminal. It is officially deprecated in this environment.
- Any future terminal integrations or keybinds must be applied to ~/.config/wezterm/wezterm.org.
- The WTQ hotkey issue must be investigated. Why does WTQ fail to attach or spawn when "WindowTitle": "^Quake$" is present, even though the OS window eventually gets named ""Quake""?
