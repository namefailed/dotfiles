** Overview & Architecture

Kanata is a highly advanced, kernel-level keyboard remapper. In this system architecture, Kanata sits at the absolute bottom of the input stack—intercepting keystrokes *before* the Windows OS, Komorebi, or any applications see them.

** Why Kanata?**
By intercepting keys at the driver level, we can implement complex logic like Tap-Hold modifiers (e.g., tapping 'F' outputs 'f', holding 'F' acts as 'Shift') and dedicated layers without relying on clunky OS-level utilities like AutoHotkey. This guarantees zero latency and zero key-eating by Windows Menus.

** Philosophy

Five principles drive this layout:

- *No corner reaching.* Modifiers live on the home row: ASDF = Meta/Alt/Ctrl/Shift
  left; JKL; = Shift/Ctrl/Alt/Meta right.
- *Layer separation.* Each trigger key owns one domain — Caps (Vim), backtick
  (mouse), LAlt (WM), LWin (launcher), apostrophe (left numpad), Tab (right
  numpad) — preventing cross-layer collisions.
- *Re-injection for passthrough.* LAlt and LWin re-inject themselves as virtual
  keys alongside the layer activation, so unbound combos pass through to the OS
  (Alt+Tab, Win+Tab, Start menu).
- *Driver-level WM control.* Komorebi bindings fire at the Kanata level before any
  application sees the key, eliminating the "first Alt press eaten by the menu bar"
  problem.
- *Ergonomic layer shortcuts.* G and H serve as home-row reach-in triggers for the
  Komorebi layer, eliminating the need to move the left hand off the home row.

** Naming Conventions

All aliases follow a consistent prefix scheme so the purpose of any binding is
clear at a glance:

| Prefix        | Domain                    | Example              |
|---------------+---------------------------+----------------------|
| =@kwm-=      | Komorebi WM actions       | =@kwm-h= (focus left) |
| =@kwl-=      | App launcher actions      | =@kwl-f= (Firefox)  |
| =@b-win=     | B key as Win modifier     | =@b-win=             |
| =@g-wm= / =@h-wm= | Home-row Komorebi layer triggers | =@g-wm=      |
| =@lalt-kwm=  | LAlt + Komorebi layer     | =@lalt-kwm=          |
| =@lmet-app=  | LWin + launcher layer     | =@lmet-app=          |

the =kwl-= prefix feeds into the =lmet-launcher= layer (app launch scripts).

** Timing and Hand Groups

260ms tap window: keystrokes faster than this always produce the letter.
200ms hold time: a key must be held this long before the modifier or layer fires.

The hand key groups feed into =tap-hold-release-keys= as *guard lists*. Kanata
resolves the tap/hold ambiguity by three rules, in order of precedence:

1. *Guarded key pressed* while waiting → fires the tap action immediately (you
   were typing, not chording).
2. *Non-guarded key fully pressed and released* while still holding → fires the
   hold action early (deliberate chord or layer use).
3. *Hold timeout* (200ms) elapses without any of the above → fires the hold action.

For the HRMs, each hand's keys guard only against the same-hand group: rolling
home-row fingers together (typing) triggers rule 1 and produces letters; reaching
across with the opposite hand (chording) triggers rule 2 and produces the modifier.

For G, H, Tab, and apostrophe — the new layer triggers — the guard is chosen so
that keys on the *same side as the layer's target keys* are never in the guard list.
G and H both trigger the Komorebi layer whose nav keys (H/J/K/L) live on the right
hand, so both are guarded by =$left-hand-keys= regardless of which physical hand
they sit on. Apostrophe triggers the left-hand numpad and is therefore guarded by
=$right-hand-keys=; Tab triggers the right-hand numpad and is guarded by
=$left-hand-keys=.

#+begin_src conf
(defvar
  tap-time 260
  hold-time 200

  left-hand-keys (
    caps
    q w e r t
    a s d f g
    z x c v b
  )

  right-hand-keys (
    y u i o p
    h j k l ;
    n m , . /
  )
)
#+end_src

** Anti-Misfire Mechanism

After any HRM tap, Kanata briefly switches to the =nomods= layer — a plain
passthrough with no modifiers — and returns to =default= on the next idle tick.
This nomods window prevents a fast keystroke after an HRM tap from triggering a modifier while the hold timer resolves.

#+begin_src conf
(deffakekeys
  to-default (layer-switch default)
)
#+end_src

#+begin_src conf
(defalias
  tap (multi
    (layer-switch nomods)
    (on-idle-fakekey to-default tap 20)
  )
)
#+end_src

** Home-Row Mods

=tap-hold-release-keys= is the safest HRM variant. It resolves tap vs. hold not
on a timer alone but on whether a guarded (same-hand) key was pressed and released
before the hold time expired. This eliminates most false modifier triggers during
fast typing without adding perceptible latency.

#+begin_src conf
(defalias
  ;; Left hand: Meta / Alt / Ctrl / Shift
  a-hrm    (tap-hold-release-keys $tap-time $hold-time (multi a @tap) lmet $left-hand-keys)
  s-hrm    (tap-hold-release-keys $tap-time $hold-time (multi s @tap) lalt $left-hand-keys)
  d-hrm    (tap-hold-release-keys $tap-time $hold-time (multi d @tap) lctl $left-hand-keys)
  f-hrm    (tap-hold-release-keys $tap-time $hold-time (multi f @tap) lsft $left-hand-keys)

  ;; Right hand: Shift / Ctrl / Alt / Meta
  j-hrm    (tap-hold-release-keys $tap-time $hold-time (multi j @tap) rsft $right-hand-keys)
  k-hrm    (tap-hold-release-keys $tap-time $hold-time (multi k @tap) rctl $right-hand-keys)
  l-hrm    (tap-hold-release-keys $tap-time $hold-time (multi l @tap) ralt $right-hand-keys)
  semi-hrm (tap-hold-release-keys $tap-time $hold-time (multi ; @tap) rmet $right-hand-keys)
)
#+end_src

** Layer Triggers

Layer triggers split into two families based on whether the key is also a typing
key and therefore needs same-hand guarding.

*Instant-activate triggers* use =tap-hold-press=: the hold action fires as soon as
the key has been held for 200ms, with no additional conditions. This is safe for
Caps Lock, backtick, LAlt, LWin, and B because none of them appear in normal prose
(the B letter rarely takes a held finger long enough to cross the hold threshold).

*Guarded triggers* use =tap-hold-release-keys=: the same mechanism as the HRMs.
This is required for Tab, apostrophe, G, and H — all real typing keys — to prevent
accidental layer activation during fast input. See [[*Timing and Hand Groups]] for the
full explanation of how the guard lists are chosen.

=lalt-kwm= and =lmet-app= both use =multi= to re-inject their physical key alongside
the layer activation. Any key not bound in those layers reaches the OS carrying the
re-injected modifier, keeping Alt+Tab, Win+Tab, and the Start menu working.

#+begin_src conf
(defalias
  ;; ── Instant-activate (non-typing keys) ──────────────────────────────────

  ;; CapsLock: Esc on tap, Vim navigation layer on hold.
  ;; Uses tap-hold-PRESS (not release-keys) because CapsLock is never rolled
  ;; with other keys in normal typing — no guard needed.
  cap       (tap-hold-press 200 200 esc (layer-while-held vim))

  ;; Backtick/grave: ` on tap, mouse movement layer on hold.
  grv-mouse (tap-hold-press $tap-time $hold-time grv (layer-while-held mouse))

  ;; LAlt: always fires lalt AND activates the Komorebi WM layer simultaneously.
  ;; Re-injection ensures Alt+Tab and similar OS combos still reach Windows when
  ;; the key pressed alongside LAlt is not bound in the komorebi layer.
  lalt-kwm  (multi lalt (layer-while-held lalt-komorebi))

  ;; LWin: tap = Ctrl+Space (Flow Launcher), hold = lmet + app launcher layer.
  ;; Tap replaces the Start menu with Flow Launcher. Hold activates the launcher
  ;; layer (F=Firefox, J=journal, etc.) and unbound keys pass through as Win+key.
  ;; 150ms hold time keeps quick Win+chord muscle memory working.
  lmet-app  (tap-hold-press $tap-time 150 C-spc (multi lmet (layer-while-held lmet-launcher)))
)
#+end_src

#+begin_src conf
(defalias
  ;; ── Guarded triggers — numpad layers ────────────────────────────────────

  ;; Tab: Tab on tap, RIGHT-hand numpad layer on hold.
  ;; Guard: $left-hand-keys. The numpad keys (U/I/O/J/K/L/Y) are all right-hand.
  ;; Pressing any left-hand key while Tab is pending fires Tab immediately so
  ;; normal Tab usage (indent, completion, shell) is never disrupted. Deliberately
  ;; holding Tab and then pressing a right-hand key triggers the numpad layer.
  tab-numr  (tap-hold-release-keys $tap-time $hold-time tab (layer-while-held numpad-right) $left-hand-keys)

  ;; Apostrophe: ' on tap, LEFT-hand numpad layer on hold.
  ;; Guard: $right-hand-keys. The numpad keys (Q/W/E/A/S/D/R) are all left-hand.
  ;; Pressing any right-hand key while ' is pending fires ' immediately, keeping
  ;; contractions and closing quotes safe at any typing speed.
  ;; Deliberately holding ' and then pressing a left-hand key triggers the numpad.
  apos-numl (tap-hold-release-keys $tap-time $hold-time ' (layer-while-held numpad-left) $right-hand-keys)
)
#+end_src

#+begin_src conf
(defalias
  ;; ── Guarded triggers — Komorebi home-row shortcuts ──────────────────────
  ;;
  ;; G and H provide direct access to the Komorebi layer without reaching for LAlt.
  ;; They activate the SAME lalt-komorebi layer as LAlt does, but without re-injecting
  ;; lalt — so unbound keys in the layer pass through as bare keys, not Alt+key.
  ;;
  ;; Both use $left-hand-keys even though H is a right-hand key, because Komorebi
  ;; commands (H/J/K/L for focus/move, 1–8 for workspaces, [/] for stacks) are
  ;; right-hand keys. Guarding with right-hand keys would fire a tap on the first
  ;; Komorebi key press, defeating the purpose. Guarding with left-hand keys means
  ;; typing through G or H fires the letter immediately; deliberate hold followed
  ;; by a right-hand komorebi key triggers the layer.

  ;; G: letter g on tap, Komorebi WM layer on hold.
  g-wm (tap-hold-release-keys $tap-time $hold-time g (layer-while-held lalt-komorebi) $left-hand-keys)

  ;; H: letter h on tap, Komorebi WM layer on hold.
  h-wm (tap-hold-release-keys $tap-time $hold-time h (layer-while-held lalt-komorebi) $left-hand-keys)
)
#+end_src

#+begin_src conf
(defalias
  ;; B: letter b on tap, LWin + app launcher layer on hold (like physical LWin).
  ;; Uses tap-hold-release-keys (guarded with $left-hand-keys) — B is typed
  ;; often enough in left-hand rolls (cab, bat, sub) that the unguarded variant
  ;; could fire the hold accidentally during fast roll-through.

* Plain Passthrough Profile
:PROPERTIES:
:header-args:conf: :tangle kanata-plain.kbd :noweb yes
:END:

Stock keyboard behaviour with no remapping. Activated by =Ctrl+Shift+NumLock=
from the main profile via =toggle-kanata-profile.ps1=. Only =caps=, =lctl=,
=lsft=, and =nlck= are intercepted — just enough to keep the toggle combo working
so you can switch back.

#+begin_src conf
;; =============================================================
;; DO NOT EDIT THIS FILE DIRECTLY.
;; Generated from ~/.config/kanata/kanata.org
;; Edit that file, tangle with `tangle ~/.config/kanata/kanata.org`,
;; then restart Kanata via Ctrl+Shift+NumLock twice.
;; =============================================================

(defcfg
  process-unmapped-keys yes
  danger-enable-cmd yes
)

(defsrc
  caps lctl lsft nlck
)

(defalias
  profile-toggle (switch
    ((and (input real lctl) (input real lsft)))
      (cmd wscript.exe //B "<<config-scripts-fwd>>/komorebi/run-powershell-silent.vbs"
           "<<config-scripts-fwd>>/kanata/toggle-kanata-profile.ps1") break
    ()
      nlck break
  )
)

(deflayer default
  caps lctl lsft @profile-toggle
)
#+end_src
