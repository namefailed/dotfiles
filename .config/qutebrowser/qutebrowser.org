* Overview

qutebrowser is a Python/Qt keyboard-driven browser with built-in vim
keybindings.  This config applies a Catppuccin Mocha colour scheme, sane
defaults (privacy, downloads, tabs), and aliases that match the rest of
the ecosystem (=C-h/j/k/l= for window navigation, consistent search
engines, adblock integration).

# ── Window decorations (frameless via Qt FramelessWindowHint / WS_POPUP) ─
# Keep this block unless qutebrowser/Qt changes its window API again.
#
# Why this exists:
# - qutebrowser 3.x on Windows runs on Qt 6 / PyQt6.
# - c.window.hide_decoration is not enough here: on this setup it can remove
#   the min/max/close buttons without reliably removing the actual title bar.
# - Komorebi's remove_titlebar_applications rule is still useful, but by itself
#   it did not remove qutebrowser's title bar in testing.
# - Setting Qt.WindowType.FramelessWindowHint on qutebrowser's main window is
#   the piece that actually made the title bar disappear again.
#
# Important implementation details:
# - Use qutebrowser's own Qt compatibility imports, not PyQt5/PyQt6 directly.
#   qutebrowser exposes Qt through qutebrowser.qt.*.
# - Use objreg to get the real qutebrowser main window. QApplication.activeWindow
#   was unreliable during config loading.
# - Config is read before the main window is always registered, so retry with
#   QTimer.singleShot until objreg can return the window.
# - FramelessWindowHint maps to a native frameless/WS_POPUP-style window on
#   Windows, so DWM does not draw the normal title bar.
from qutebrowser.qt.core import QTimer, Qt
from qutebrowser.utils import objreg


def _frameless():
    try:
        win = objreg.get("main-window", scope="window", window=0)
    except objreg.NoWindow:
        # The main window is not registered yet during early config load.
        # Retry shortly instead of failing config.py startup.
        QTimer.singleShot(50, _frameless)
        return

    flags = win.windowFlags()
    win.setWindowFlags(flags | Qt.WindowType.FramelessWindowHint)

    # Changing Qt window flags can hide/recreate the native window; show() makes
    # the updated native style visible immediately.
    win.show()


QTimer.singleShot(0, _frameless)

# ── Global Qt tooltip suppression ───────────────────────────────────
# qutebrowser's tabs.tooltips only covers tab hover text. QtWebEngine and
# other widgets can still request native QToolTip windows, which Komorebi sees
# as independent top-level windows. Block tooltip events at QApplication level
# and make direct QToolTip.showText calls no-op.
try:
    from qutebrowser.qt.core import QObject, QEvent
    try:
        from qutebrowser.qt.widgets import QApplication, QToolTip
    except Exception:
        from PyQt6.QtWidgets import QApplication, QToolTip

    class _NoToolTipFilter(QObject):
        def eventFilter(self, obj, event):
            tooltip_events = {
                getattr(QEvent.Type, "ToolTip", None),
                getattr(QEvent.Type, "ToolTipChange", None),
                getattr(QEvent.Type, "WhatsThis", None),
            }
            if event.type() in tooltip_events:
                try:
                    QToolTip.hideText()
                except Exception:
                    pass
                return True
            return False

    def _disable_qt_tooltips():
        app = QApplication.instance()
        if app is None:
            QTimer.singleShot(50, _disable_qt_tooltips)
            return

        def _noop_tooltip(*args, **kwargs):
            try:
                QToolTip.hideText()
            except Exception:
                pass
            return None

        for attr in ("showText", "show_text"):
            if hasattr(QToolTip, attr):
                try:
                    setattr(QToolTip, attr, staticmethod(_noop_tooltip))
                except Exception:
                    pass

        global _no_tooltip_filter
        try:
            app.removeEventFilter(_no_tooltip_filter)
        except Exception:
            pass
        _no_tooltip_filter = _NoToolTipFilter(app)
        app.installEventFilter(_no_tooltip_filter)

        for widget in app.allWidgets():
            for setter in ("setToolTip", "setStatusTip", "setWhatsThis"):
                if hasattr(widget, setter):
                    try:
                        getattr(widget, setter)("")
                    except Exception:
                        pass
        try:
            QToolTip.hideText()
        except Exception:
            pass

    QTimer.singleShot(0, _disable_qt_tooltips)
except Exception:
    pass

# ── Qt popups/tooltips (Komorebi rule dependency) ───────────────────
# The right-click context menu in Qt6 creates a separate OS window with
# classes like Qt\\d+QWindowPopup.*. Tab hover tooltips use
# Qt*QWindowTool* classes; disable tab tooltips with c.tabs.tooltips = False,
# then suppress all native Qt tooltip events with the global filter above.
#
# The fix lives in komorebi.org (Floating Applications section):
#   Exe: qutebrowser.exe + Class: Qt\\d+QWindowPopup.*
#
# If the popup class changes with a Qt version upgrade, re-identify it with:
#   komorebic visible-windows   (run while context menu is visible)

* Dark Mode

Chromium's built-in dark mode forces a dark scheme on pages that don't
support it natively.  The =gr= key toggles it on/off.

A user stylesheet (=dark-bg.css=) sets the =html= background to
Catppuccin Mocha base (#1e1e2e) before any page CSS loads, which
eliminates the white flash on new tabs.  No =!important= — page styles
take over normally once loaded.

#+begin_src python :tangle config.py
# Disable dark mode globally
c.colors.webpage.bg = "#1e1e2e"
c.colors.webpage.darkmode.enabled = False
c.colors.webpage.preferred_color_scheme = "dark"

# Toggle on/off per page (config-cycle flips booleans)
config.bind("gr", "config-cycle colors.webpage.darkmode.enabled")

# Reader mode (extract article content, open in new tab)
config.bind("gR", "spawn --userscript readability.bat")
#+end_src

* Reader Mode (Readability)

Qutebrowser has no built-in reader mode.  This setup uses the
=readability-lxml= Python library (a port of Mozilla's Readability.js)
extracted via a userscript that opens the cleaned article in a new tab.

** Keybinding

Already defined above in the Dark Mode section:

#+begin_example
gR  →  spawn --userscript readability.bat
#+end_example

** Files

The userscript source files live at =~/.config/qutebrowser/userscripts/=.
A directory junction makes them visible to qutebrowser at the default
Windows userscript path:

| Junction target | ← Junction source |
|-----------------|-------------------|
| =~/.config/qutebrowser/userscripts/= | =%APPDATA%\qutebrowser\data\userscripts\= |

Two files:

| File | Purpose |
|------|---------|
| =readability.bat= | Windows batch wrapper (qutebrowser spawns only =.com=/.bat=/.exe=) |
| =qute_readability.py= | Python script: extracts article, wraps in styled HTML, opens in new tab |

The =.bat= wrapper calls =python.exe= via its full path to the system
Python 3.14 install (=%LOCALAPPDATA%\Programs\Python\Python314\=), not
another Python venv where =readability-lxml= is not installed.

** Python dependency

Install once:

#+begin_src powershell
& "$env:USERPROFILE\AppData\Local\Programs\Python\Python314\python.exe" -m pip install readability-lxml
#+end_src

=breadability= (a fork) is tried first, then falls back to =readability=
if absent.  Only =readability-lxml= is currently installed.

** How it works

1. qutebrowser captures the current page's HTML + URL
2. qutebrowser launches =readability.bat= via =--userscript=
3. =.bat= runs =qute_readability.py= with system Python 3.14
4. Script reads the saved HTML via =QUTE_HTML= env var
5. =readability.Document= extracts a cleaned article (title + body)
6. Script wraps the article in a styled HTML page and writes it to a temp file
7. Script writes =open -t <tmpfile>= into =QUTE_FIFO=, which qutebrowser reads

** Bug history: =% formatting vs CSS =%=

The HEADER template originally used Python =%s= string formatting:

#+begin_example
HEADER % title
#+end_example

When the CSS was upgraded with =max-width: 100%=, Python's =%=
interpreter saw the =%= in the CSS as a format specifier, producing:

#+begin_example
TypeError: not enough arguments for format string
#+end_example

Fix: switched to Python =.format()=:

#+begin_example
HEADER.format(title=title)
#+end_example

This required:
- Changing =%s= to ={title}= in the template
- Doubling all CSS braces (={{= → ={{=, =}}= → =}})=) so =.format()= treats
  them as literal characters

See also: the same bug can happen with =%(= if =percent= is used literally
in CSS (e.g., =width: 50%()= in a .format() string — not an issue here
since =%()= isn't a CSS construct in this stylesheet).

** Fix: =codecs.open= deprecation

The original script used =codecs.open(... , "r", "utf-8")= which is
deprecated since Python 3.13+.  Replaced with:

#+begin_example
open(..., "r", encoding="utf-8")
#+end_example

** CSS design

The readability stylesheet is designed to:

- Respect qutebrowser's dark mode toggle (=gr=) by using =currentColor=
  and =rgba()= with no hardcoded foreground/background colours
- Center images, figures, and block-level media (=display: block; margin: 2rem auto=)
- Use a readable font stack (system fonts with fallback)
- Style code blocks, tables, blockquotes, and horizontal rules
- Scale comfortably on mobile via =viewport= meta tag

Key CSS choices:

| Rule | Purpose |
|------|---------|
| =max-width: 720px= | Comfortable reading width |
| =line-height: 1.7= | Generous leading for readability |
| =rgba(128,128,128,0.12)= backgrounds | Semi-transparent =:hover= effects that work on any background |
| =currentColor= for borders | Inherits the page's text colour (works with dark mode toggle) |
| =max-width: 100%; height: auto= on images | Prevents overflow on narrow screens |

* Greasemonkey

A Greasemonkey-compatible userscript strips HTML =title= attributes from
all pages at =document-start=, preventing QtWebEngine from creating native
tooltip windows from web content.  A MutationObserver catches dynamically
added =title= attributes or new DOM nodes.

Enabled via =c.content.greasemonkey = True= in the Privacy section above.
Without this setting, qutebrowser ignores the =greasemonkey/= directory.

File: =~/.config/qutebrowser/greasemonkey/disable-hover-tooltips.user.js=

** Keybindings

All keybindings are ported from the Tridactyl-on-Firefox config to match
existing muscle memory.  Notable differences from qutebrowser defaults:

- =H= / =L= switch tabs (qutebrowser defaults: history back/forward)
- =J= / =K= go back/forward in history (qutebrowser defaults: tab prev/next)
